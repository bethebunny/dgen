# Existential types in Mojo, in-language

A prototype of `Any` / `trait_cast` / `cast` for **Mojo 1.1.0** (`pip install mojo`),
with no compiler changes. Unrelated to dgen; it lives on this branch only to persist it.

```bash
./run_tests.sh                       # demo, runtime tests at -O0 and default, compile-fail tests
mojo build -I . bench.mojo -o bench && ./bench
```

## Verdict

**It works.** Everything in the target sketch runs at full optimisation and is clean under ASan. LSan's only report is the optional registry's intentional process-lifetime buffer:

```mojo
comptime dyn = Existential[DynMyTrait, DynMySubTrait, DynSomeOtherTrait]  # the "universe"
comptime Any = dyn.Any
comptime trait_cast = dyn.trait_cast

var ts: List[Any[MyTrait]] = [Foo(7), Bar("hello")]
ref t = trait_cast[MySubTrait](ts[0])   # runtime-checked; `t` aliases ts[0], no copy
t.method(); t.sub_method()
use_generically(t)                      # t really conforms to MySubTrait
ref foo2 = cast[Foo](t)                 # ref Foo into the box
cast[Int](t)                            # raises: cannot cast demo.Foo to SIMD[DType.int, 1]
trait_cast[SomeOtherTrait](t)           # raises: demo.Foo does not conform to ...
ts[1][].method()                        # infallible view as the base trait
```

The differences from the sketch, and why:

| Sketch | Prototype | Why |
|---|---|---|
| `struct Witness[T: AnyTrait](T)` | `Witness[Tr]` is a `comptime` alias that resolves to a per-trait adapter struct | A struct can't conform to a trait *parameter* (probe 01). |
| Witness generated by reflection | One hand-written adapter per trait. Each line is mechanical, e.g. `thunk[T.method]` | Reflection can't enumerate a trait's methods. |
| Any trait can be queried | Traits must be in a closed **universe** `Existential[...]`, or registered at runtime | No globals or static initialisers (probe 04), so nothing can collect `(T, Trait)` pairs across sites. |
| `List[MyTrait]` | `List[Any[MyTrait]]` | A trait isn't a type. |
| Witness by value | `ref` only | See avenue 6. Your sketch already used `ref t = ...`. |

## How it works

```
Any[Base] (16 B)          TypeMeta  (rodata, one per T)         ShapeVT (rodata, one per (T, Trait))
┌──────────┬──────────┐   ┌───────────────────────────────┐     ┌──────────────────────┐
│ data* ───┼→ heap T   │   │ type_tag  : fn  (= identity)  │     │ area: thunk[T.area]  │
│ meta* ───┼──────────────→│ destroy   : fn                │     └──────────────────────┘
└──────────┴──────────┘   │ clone     : fn  (0 if !Copy)  │               ↑
       ║ same layout       │ witness   : fn(adapter) → vt* ┼───────────────┘
       ▼                   └───────────────────────────────┘
DynShape { _h: Header }   ← trait_cast reinterprets the Any in place as this
  def area(self): return self._h.vtable[Self]().area(self._h.data)
```

- **Type identity** is the address of `_type_tag[T]`, a `@no_inline` generic function. Its body returns `T`'s name, so identical-code-folding can't merge two instantiations.
- **`TypeMeta` and every vtable are compile-time constants placed in rodata** via `global_constant`. This is the "singleton per type" metadata idea: `Any` is `{data*, meta*}`, like a Swift existential container without the inline buffer.
- **`TypeMeta.witness(adapter_key)`** is generated per `T` by `comptime for` over the universe, with `comptime if conforms_to(T, D.Trait)` deciding which arms exist. The arm returns the address of the static vtable for `(T, D)`.
- **Adapters are layout-identical to `Any`** (a single `Header` field). So `trait_cast` returns `ref[x] Witness[Tr]` that *aliases* `x` (an `Any` or another witness), with no allocation or copy.
- **`Witness[Tr] = downcast[Adapters[index_of[Tr]()], Tr]`.** `index_of` compares traits at compile time with `#kgen.param.identical`.
- **Optional open world.** `register[T, DynX]()` (checked at compile time that `T: DynX.Trait`) appends to a runtime table in `std.ffi._Global`. `trait_cast_via[DynX](x)` names the adapter instead of the trait and consults both the universe and the table.

Rough dispatch cost (`bench.mojo`, one machine, ns/call):

| Call | ns/call |
|---|---|
| static generic call | ≈1.0 |
| ideal fat-pointer `{data*, fn*}` call | ≈2.2 |
| `any[].area()` | ≈2.6 |
| same, with the trait 3rd in the universe | ≈3.0 |

The per-call witness lookup costs ≈0.4–0.8 ns over the ideal fat pointer.

## Investigation log

Links are pinned to the `mojo/v1.1.0` tag of [modular/modular](https://github.com/modular/modular/tree/mojo/v1.1.0/Mojo).
Probes are in `probes/`, and each one runs standalone (`mojo run -I . -I .. probes/pNN_*.mojo`).

1. **Can `Witness[U]` conform to `U` generically?** No.
   `structs only conform to traits or trait compositions; remove the type parameter`.
   → `probes/p01`. The workaround is the per-trait adapter plus a compile-time lookup (avenue 5).

2. **Traits as values.** Yes, `Trait: type_of(AnyType)` parameters work:
   - `conforms_to(T, Trait)` is a compile-time `Bool`.
   - `comptime if conforms_to(...)` *refines* `T` inside the branch.
   - `downcast[T, Trait]` refines explicitly.
   - Trait identity is available through `#kgen.param.identical`.

   Refs:
   [`rebind.mojo` (`downcast`)](https://github.com/modular/modular/blob/mojo/v1.1.0/Mojo/stdlib/std/builtin/rebind.mojo#L111),
   [type refinement, v1.0.0b1 notes](https://github.com/modular/modular/blob/mojo/v1.1.0/Mojo/docs/site/releases/v1.0.0b1.md#L125),
   [`trait_downcast` removed, v1.1.0 notes](https://github.com/modular/modular/blob/mojo/v1.1.0/Mojo/docs/site/releases/v1.1.0.md#L678),
   [trait identity test](https://github.com/modular/modular/blob/mojo/v1.1.0/Mojo/test/mojo-integration/trait_value_parameter.mojo),
   [`_plugin/selector.mojo`](https://github.com/modular/modular/blob/mojo/v1.1.0/Mojo/stdlib/std/_plugin/selector.mojo) (stdlib precedent for trait-indexed type lists).

3. **Reflection.** It gives fields, names, offsets and annotations, but not trait methods. So a witness can't be generated from the trait.
   [`reflect.mojo`](https://github.com/modular/modular/blob/mojo/v1.1.0/Mojo/stdlib/std/reflection/reflect.mojo#L127),
   [reflection manual](https://github.com/modular/modular/blob/mojo/v1.1.0/Mojo/docs/site/manual/metaprogramming/reflection.mdx).

4. **Global registration**, à la Rust `inventory`/`linkme` or Swift conformance records:
   - `global variables are not supported` → `probes/p04`. There are no static initialisers either.
   - But `std.ffi._Global[name, init_fn]` is a lazily created, runtime-backed named global. It's private API, but importable, and it backs the optional registry.

   Ref: [`ffi/__init__.mojo`](https://github.com/modular/modular/blob/mojo/v1.1.0/Mojo/stdlib/std/ffi/__init__.mojo#L1023).

5. **Universe lookup `Witness[Tr] = downcast[Adapters[index_of[Tr]()], ...]`.**
   - `downcast[X, Tr]` with a parametric `Tr` **works** → `probes/p08`.
   - `downcast[X, Tr & TraitAdapter]` **loses `Tr`** when `X` is unresolved → `probes/p07`.

   As a result, a witness is known *only* as `Tr`, which isn't `Movable` or `Deinitable`. It can therefore only be handed out by `ref`.

6. **Copying the vtable into the witness, i.e. a fat pointer by value.** Rejected because of avenue 5. Instead, adapters share `Any`'s layout and fetch the static vtable on each call. A by-value `Dyn[Tr]{data*, vt*}` with `t[]` access is possible if per-call speed matters more.

7. **Vtables via thin function pointers.**
   - The stdlib already does this by hand: [`_ErasedWriter` in `format/tstring.mojo`](https://github.com/modular/modular/blob/a1ccd09/Mojo/stdlib/std/format/tstring.mojo#L28) (on `main`).
   - `global_constant[value]()` puts a struct of function pointers in rodata at a stable address → `probes/p10`. [`globals.mojo`](https://github.com/modular/modular/blob/mojo/v1.1.0/Mojo/stdlib/std/builtin/globals.mojo#L22).
   - A `Tuple` of function pointers is rejected by `global_constant` (`Tuple` isn't trivially copyable), so vtables stay as structs.

8. **Unbound methods as compile-time function values.** `thunk[T.area]`, with `f: def(T) thin -> R` as the parameter, works even for an abstract `T: Trait` → `probes/p12`. It removes all hand-written thunks.

9. **Runtime type id** = address of a generic function → `probes/p05`. It's stable under `downcast` → `probes/p09`.

10. **Heisenbug (my bug, not Mojo's).** The first version wrote the vtable into a stack `MaybeUninit` through a pointer cast to `MutUntrackedOrigin`. At `-O0` it worked; at the default level the success path was optimised away. Printing the result "fixed" it.
    The cause: hiding a mutation from origin tracking lets the compiler assume the slot is still uninitialised. The fix is to keep the pointer's origin tracked: `MutOpaquePointer[_]` in the function-pointer type, which stdlib's `_ErasedWriter` also does. v2 sidesteps it entirely with static vtables.

## Compiler issues found (worth filing upstream)

1. **Soundness:** in `T: Self.Base & Movable`, where `Base: type_of(AnyType)` is a *parameter*, the compiler silently drops `Self.Base`. The only hint is the warning "redundant trait composition: 'Movable' already implies 'AnyType'". → `probes/p11` stores an `Int` in a `Box[Greet]`.
   Workaround: `where conforms_to(T, Self.Base)` (`compile_fail/base_bound.mojo`).
2. **ICE:** `CallParamInf::inferForCall` crashes when calling `D.adapt[T]()`, where `D` comes from a variadic type pack and `T` is refined only by `comptime assert conforms_to(T, D.Trait)` → `probes/p06`.
   Workaround: pass `downcast[T, D.Trait]` explicitly.
3. **Composition loss:** `downcast[X, Tr & Other]` with a parametric `Tr` and an unresolved `X` loses `Tr` → `probes/p07`. Probably the same root cause as #1.

## Adding traits after the universe is defined

Each `Any`'s metadata is generated when the value is boxed, from that universe's adapter list. A trait added later is invisible to already-boxed values unless it's registered at runtime. What does work:

| Approach | Mechanism | Who sees the new trait | Probe/test |
|---|---|---|---|
| **Extend at compile time** | `comptime app = lib.Extend[DynNew]`, a new and larger universe built with `TypeList._concat` | Values boxed under `app`. `lib.Any` and `app.Any` are distinct, non-convertible types. | `probes/p13`, `test_extend_universe` |
| **Library generic over the universe** | `def make[*Ad: TraitAdapter]() -> AnyBox[Shape, *Ad]` | Whatever universe the caller instantiates. Every API that touches `Any` has to carry the parameter. | `probes/p13` |
| **Late binding by import path** | The library does `from existential_universe import universe`, and each app puts its own `existential_universe.mojo` on `-I` | The whole program, assembled at build time. Source builds only: a precompiled `.mojopkg` would bake in its import. | `probes/latebind/` |
| **Runtime registration** | `register[T, DynNew]()` per `(type, trait)` pair, checked at compile time that `T: DynNew.Trait` | Every `Any` holding `T`, including values already boxed | `probes/p13`, `test_open_world_registry` |
| **Retroactive conformance** | `unsafe_register_as[T, DynNew, vtable]()` with a hand-built vtable over free functions | Same as above, for types that *never declared* the trait. The traits manual says "You can't add traits to existing types"; the undocumented `__extension` can only partly (see below). | `probes/latebind/app_b`, `test_retroactive_conformance` |

**A `comptime` list in `Any`, appended to by registration?** Holding the list works: `AnyBox[Base, *list]`, where `list` is a `TypeList` value, is equivalent to the variadic form (`probes/p14`). Appending doesn't. Compile-time evaluation runs ordinary code, so a function can *build* a list with `append`. But a named `comptime` value is an rvalue: `xs.append(3)` is "invalid use of mutating method on rvalue", and re-declaring `xs` is "invalid redefinition" (`probes/p15`). (`TypeList`, the compile-time list of *types*, has no `append` at all; all its operations return new lists.) Every "append" is therefore a new list under a new name, which gives a new `Any` type; that's exactly `Extend`. What separate registrations would need is a list that is finalised *after* every registration but *before* any `Any` is instantiated, i.e. assembled once for the whole program. In 1.1 the only way to get that is the import-path trick above. Upstream `main` (after 1.1) adds something close: a compilation target can carry an `opaque_plugin` type list, read with `#kgen.get_target_plugin` ([test](https://github.com/modular/modular/blob/a1ccd09/Mojo/test/mojo-integration/compile_offload/target_plugin.mojo)). It's still set in one place, when the target is constructed, not appended to by declarations.

What *can't* work: registering a trait on its own ("make `DynNew` available for every type") at runtime. A vtable for `(T, NewTrait)` is code that must be instantiated with both known at compile time. At boxing time only `T` is known, at cast time only the trait, and there's no JIT in a built binary. Swift avoids this because the compiler emits conformance records; Rust doesn't offer it at all.

## `__extension` (undocumented, Mojo 1.1)

Mojo has no documented extension blocks: they're absent from the 1.1 docs and from upstream `main`, and `extension`/`extend`/`impl` are syntax errors. Conditional conformance *does* exist, but only on the struct's own declaration: `struct Box[T](Equatable where conforms_to(T, Equatable))` ([reference](https://github.com/modular/modular/blob/mojo/v1.1.0/Mojo/docs/site/reference/struct-declarations.mdx#L323)).

The compiler does accept an underscored `__extension` keyword. What it does (`probes/extension/`):

| Use | Result |
|---|---|
| `__extension Point:` adding methods, even to a type from another module or to `String` | Works |
| `__extension Point(Greet):` where `Greet` is declared in the *same* module | Generic calls accept it, but `conforms_to(Point, Greet)` is still `False` (p16) |
| `__extension Point(Greet):` where `Greet` is *imported* | Rejected: "'Point' does not implement all requirements for 'Greet'" (p17) |
| `__extension Wrapper(Greet where ...)` | Rejected: "'where' clauses in conformance lists are only supported on structs" |

Because `conforms_to` ignores extension conformances, the universe machinery never sees them, and `Any[Greet]` refuses to box such a type. What does work today is a method-only extension plus the registry: `__extension Point: def greet(...)`, then `unsafe_register_as[Point, DynGreet, GreetVT(thunk[Point.greet])]()` (p18).

## Taking the value back out

```mojo
var foo = any^.take[Foo]()        # moves Foo out; frees only the box
if any.isa[Foo](): ...            # exact-type check
try:
    var bar = any^.take[Bar]()
except e:                         # e: TakeError, a typed error (Mojo 1.1)
    var any2 = e^.into_value()    # on mismatch the Any comes back, like Rust's Err(self)
```

`take` consumes the `Any` (`deinit self`). On a match it moves `T` out of the heap box without destroying it, then frees the box. On a mismatch it raises a typed `TakeError` that owns the original `Any`, so nothing is lost and no empty state is needed. Moving a field out of a caught error is a partial move, which Mojo rejects, hence `into_value()`. The tests check the live-instance count on both paths, and the ASan build is clean apart from the registry.

## Avoiding the hand-written adapter

An adapter needs two things only the compiler can currently produce: a struct that **conforms to `Tr`**, so generic code accepts the witness, and **one named forwarding method per trait method**. Doing it in-language would need trait-method reflection plus a way to synthesize named members, or compiler-synthesized `dyn Tr` conformance, as Swift and Rust do. What was tried:

| Avenue | Outcome |
|---|---|
| **Generate adapters from `mojo doc` JSON** (`gen/gen_adapters.py`) | **Works.** `mojo doc` exports each trait's methods: argument names, conventions, types, `raises`, and parent traits. The generator emits `<Trait>VT` + `Dyn<Trait>`, including inherited methods, `mut self`, `var` args and `raises`, and skips non-dispatchable traits with a reason (a `Self` argument, a static method, a parametric method). `gen/test_gen.mojo` uses only generated adapters; `run_tests.sh` fails if the generated file is stale. |
| `__getattr__` instead of forwarding methods | A compile-time name works via `__getattr__[v](self, name: StringLiteral[v])`, and can return a callable, so `w.scale(7)` works. But it never makes a struct conform to a trait, there's no `T.<name>` lookup by string, and the per-name return type would need trait reflection. Dead end for conformance. |
| Function-type reflection to derive vtable fields | `ReflectedFn` exposes only `display_name()` / `linkage_name()`, with no argument or return types. Dead end. |
| **Closed set of candidate types + generic visitor** (`probes/p20`) | **Works, with zero adapters.** Higher-rank compile-time function parameters are supported: `f: def[T: Tr](mut T) thin -> R`. `Candidates[Sq, Tri].visit[Resizable, grow](any)` instantiates the visitor for each candidate that conforms, then dispatches by type id with static, inlinable calls. It works on an `Any` whose universe is empty. The catch is that the *types* are closed instead of the traits, named at the call site. |

`visit` is the *eliminator* for the existential: `exists T: Tr. T` is equivalent to `forall R. (forall T: Tr. T -> R) -> R`. In practice (`probes/p21`):
- **Passing to a free function that expects a refined trait works directly.** `known.visit[Resizable, describe](any)` takes an existing `def describe[T: Resizable](t: T)` unchanged. There are read and `mut` variants, and extra arguments can be forwarded.
- **Inside the visitor, `trait_cast` becomes a compile-time branch.** `comptime if conforms_to(T, Named): t.name()` handles sideways casts and subtraits without a runtime check, and the refined value can be passed on to other generic functions.
- **A refined *value* can't escape.** `R` is a single type for every `T`, so `def leak[T: Tr](t: T) -> T` is rejected. A storable `trait_cast` result needs a type that stands for "some `T: Tr`", which is exactly the adapter.

, using `visit` as a devirtualized fast path for known types and falling back to `f[Witness[Tr]]` through an adapter for unknown ones, since the witness also conforms to `Tr`. Or use runtime compilation (`std.compile` / `compile_offload`) to instantiate `(T, Tr)` vtables on demand, which would only work when running under the JIT.

## Limitations / sharp edges

- **Unsound with borrowing types.** `Any` has no origin parameter, so boxing a value that holds a reference (a `Pointer`, `Span`, ...) erases the borrow. `probes/p19` compiles and ASan reports heap-use-after-free. Rust prevents this with `dyn Trait + 'a` and the `'static` bound on `dyn Any`. Mojo has no way to say "`T` holds no origins" or "`T` outlives `o`", so this can only be documented, not prevented.
- **The universe is fixed at boxing time** (see the section above). `TypeMeta.witness` only knows the adapters of the universe the `Any` was created in. Asking it about another adapter falls through to the runtime registry, then reports "does not conform".
- **Each trait needs a vtable struct and an adapter.** Subtrait adapters re-forward parent methods; composing the parent vtable helps (`MySubTraitVT.base`).
- **Witnesses are `ref` views.** They borrow from their `Any`. There's no by-value witness. To get an owned value back out, use `any^.take[T]()` (see below).
- **`Any` is move-only.** `dyn.clone[Base](x)` copies when the erased `T` is `Copyable` and raises otherwise.
- **It relies on type punning.** That's sound only because adapters are a single `Header` field. `_header_of` asserts `Erased` and `size_of` at compile time.
- **The registry is not thread-safe** and relies on a private stdlib API. Its buffer lives for the whole process, so LeakSanitizer reports it (24 B per registration). Nothing else leaks; the tests also count live instances.

## Language features that would remove the workarounds

- Conformance to a trait parameter: `struct Witness[Tr: trait](Tr)` plus some forwarding mechanism. Alternatively, trait-method reflection so adapters can be generated.
- Static initialisers or linker-collected sections, for an open-world conformance table.
- A fix for parametric trait composition (issues 1 and 3), so `downcast[X, Tr & Movable]` gives a by-value witness.
